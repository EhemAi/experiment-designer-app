Start and installation

Extract the full distribution ZIP. For portable use, open App/ExperimentDesigner.exe. To install for your Windows account, open Setup/ExperimentDesigner.Setup.exe, review the destination and select Install / update. The package includes its own Windows runtime. Keep its App and Runtime folders together. The installer can create a desktop shortcut.

To remove an installed copy, close the app, rerun Setup, choose the same destination and select Remove installation. Unknown or modified files and study projects remain. Save your study files in a separate Documents/study folder.

Use Light mode / Dark mode in the header to switch appearance. Your choice is remembered; switching does not reload animal records or discard pending edits.

1. Configure the study

  1. Select Study and choose RCBD, completely randomized or conventional allocation.
  2. Select the experimental unit: pen or cage. Set replicates per treatment and animals per experimental unit.
  3. Enter treatments in the intended order using unique IDs and descriptive labels, or import a treatment table.
  4. Select Apply settings to record the study configuration. Add/remove or Move up/down changes treatment order only as a draft until applied.

The required animal count is treatments × units per treatment × animals per unit. Changes create input revisions; earlier allocations retain their own inputs.

Prepare sheets and labels before allocation day

  1. Apply Study settings with treatments, replicates and animals per pen or cage. Animal IDs and weights are not needed yet.
  2. Open Allocation → Overview, choose the housing range and enter a layout seed. The range must contain exactly treatments × replicates numbers. For three treatments and four replicates, 101–112 uses 101–103 for replicate 1, 104–106 for replicate 2, and so on. Treatments are randomized within each replicate.
  3. Select Prepare layout. Review the Prepared layout tab and Save the project. Print layout / labels opens Excel export, printable HTML, print preview and Print / PDF. The blank allotment sheets include one row per planned animal, with Animal ID and BW left blank; Housing labels contains one entry per pen or cage.
  4. On allocation day, reopen this saved project, use Enter animals to type IDs and weights in grams (then Review entries, Validate and preview, and Apply reviewed import), or import IDs and body weights from a file; the program automatically selects the required number of heaviest animals; then Generate allocation. A different animal-allocation seed is allowed: the saved layout seed keeps the prepared treatment locations unchanged.
  5. If treatments, replicates, animals per unit or housing range change, prepare a replacement layout and reprint the affected sheets. Replacing a layout warns that previous labels may no longer match.

Preparation records no animal allocation. Generate allocation without an existing layout prepares one automatically. Final exports list each allocated animal’s actual pen or cage number. Excluded animals have no destination. Unmapped historical results require housing assignment before final export.

2. Import and automatically choose animals

  1. Select Animals → Import animals. CSV, TSV, XLSX and XLSM are supported. Workbook macros and formulas are not executed.
  2. Choose the sheet/table, header row and complete animal row range. Map Animal ID and BW, then choose grams or kilograms. Enable stored integer IDs for numeric IDs in Excel. Review Validate and preview, then Apply reviewed import.
  3. Every imported record remains in the source pool. The required number of heaviest animals is selected automatically. Lighter animals are used as needed to fill the study; unused animals are EX. Weight ties use Animal ID then immutable Record ID. No Include/Exclude clicking or selection commit is required.
  4. If the pool is smaller than the required count, import or enter more animals. The supported pool limit is 100,000 animals. Changing study counts or correcting weights updates automatic selection.
  5. Search, filter, scroll and change page size to review records. Selected and EX are shown in Status. Go to Allocation when ready.

Original sources, measurements and the automatic selection rule are retained in the project. Existing projects with manual selections retain their historical decisions; a new animal import uses automatic selection.

3. Allocate and review

  1. Select Allocation → Overview. Enter an unsigned whole-number seed, then Generate allocation. No run reason is needed; History records the action and seed automatically. A disabled action has a visible setup/selection blocker.
  2. Review Overview, Assignments, Pen BW, Treatment balance and Diagnostics. Overview uses actual current block CV and treatment mean BW; original attempt records are available in Diagnostics. Its plot starts at zero. Scroll compact views to see all metrics and treatments. Cancellation or a failed attempt retains the previous completed result.
  3. The revision selector controls every result view and export. Historical results and results based on earlier inputs are labeled.
  4. To swap, choose the active current-input revision, open Swap animals, choose two records and supply a reason. Review the affected units/blocks and apply only a passing preview.
  5. To map housing, enter exactly one physical unit per allocation unit, using unique physical IDs, full scoped locations, sufficient capacity and replicate eligibility. Preview with its independent mapping seed before applying.

Changed swap/mapping inputs invalidate their previews. Applied operations create logged revisions. Choose Use this result with a reason to make an earlier result active.

BW balance is descriptive at the experimental unit level. It does not analyze later study outcomes. The versioned generator is not Excel RAND; edited results require the original seed and ordered edit history for replay.

New projects use .experimentproj. Existing .poultryproj files remain supported. Opening a legacy project and selecting Save prompts for a new filename, retaining the old file. Saved balancing settings, notes, layouts and history are preserved even though optimization and notes controls are no longer shown on Study.

4. Save projects and recover

Save writes a .experimentproj containing prepared layout, settings, original sources, decisions, revisions and run/edit/map history. The visible Save action (Ctrl+S) writes the project; File → Save as writes a new path. File also contains New study (Ctrl+N), Open (Ctrl+O) and Recover backup. User guide is in the sidebar. Saved, Unsaved changes, Saving and Save failed are explicit; a project without a filename is not labeled Saved. A title/status indicator marks unsaved settings or decisions. Exporting a report does not save the project.

New, Open and Close offer save/discard/cancel for dirty work. Routine settings, selection and generation actions receive descriptive history labels automatically. Reasons for corrections, swaps and housing changes remain available in their review dialogs. There is no autosave; save regularly. Saves check whether the disk file changed externally and preserve the preceding saved version as .bak.

For recovery, select File → Recover backup and choose the main project's filename. The backup is validated and must be saved to a new path. Recovery restores previously saved history, not unsaved work. A failed open leaves the current project intact.

5. Export and print

Choose a completed allocation, then select Export / print. Choose movement order by treatment/unit, old location or new location.

Excluded animals have no invented destination. Allocated animals without housing mapping say Unmapped. Printed statistics use three decimal places; full values remain in Excel and the project. Excel has about 15 significant digits of numeric precision.

History and desktop controls

History shows recent real recorded actions and the complete Runs and edits, Input revisions and Source files tables. Select Source files to inspect the retained original observations. The workflow indicator marks the current step; Review / Export means output is available, not scientifically approved. Native tabs support keyboard navigation, buttons retain visible focus, and modal prompts support Escape. On reduced windows, forms and Overview scroll while tables fill the remaining space.

The package is unsigned. The included Setup app registers installed copies in Start and Windows Installed apps. Verification examples are synthetic demonstrations. Complete the final scientific review with your real study's researcher-approved selection before operational use.

Review balance before export

The Allocation screen shows treatment ANOVA immediately after each completed run, across its result tabs. A p-value at or below 0.6 shows a repeat recommendation. Select Repeat with next seed to record a new allocation while retaining the previous result and prepared housing arrangement. This action advances the seed once; it does not automatically rerun until a target is reached. The recorded result remains available for expert review and export. A p-value that cannot be estimated requests review of unit body weights.

ANOVA and numeric Excel sorting

ANOVA compares pen/cage mean body weights. RCBD and conventional BW-blocked designs include replicate blocks; CRD uses a one-way treatment model. The displayed target is strictly p > 0.6, so 0.61 meets it. This is a baseline balance diagnostic, not proof of equal weights or a successful allocation. Zero-variance cases are labeled explicitly.

Plain numeric Animal IDs, Treatment IDs, pen/cage numbers and replicates export as Excel numbers. Leading-zero IDs, IDs longer than 15 digits and alphanumeric IDs remain text to protect identity and Excel precision. Sort or filter the unit table; the ANOVA panel sits outside its filter range.
